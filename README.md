# ebk-tg-bot

Telegram-бот для [ezBookkeeping](https://ezbookkeeping.mayswind.net/): расходы и доходы
из текста, чеков и голосовых сообщений, отчёты и остатки. Codex OAuth, локальный Whisper,
PostgreSQL, доступ по Telegram ID и обновляемый статус обработки.
Ответы оформляются заголовками и выделениями. Для коротких уточнений из 2–3 вариантов
появляются кнопки; всегда можно ответить обычным текстом своими словами.
Выписки: PDF Яндекс Банка и Т-Банка, CSV/XLSX Т-Банка (до 15 МБ, 100 страниц,
1000 операций; PDF с текстовым слоем). Просто пришлите файл: бот сам выберет подходящий
счёт, сверит дубли, предложит категории и повторно проверит решения через ChatGPT.
При неоднозначности появятся кнопки выбора счёта или категории. Подходящие категории показываются
первыми; выбор пользователя принимается сразу, без повторного обращения к модели.
Навигация привязана к номерам строк, без перехода с конца списка в начало.
Каталог заранее загружается в память и PostgreSQL, обновляется в фоне каждые 5 минут;
перед записью данные сверяются заново.
План, просмотр строк, исключение операций и подтверждение доступны кнопками под сообщением; пояснение
к открытой строке можно написать обычным текстом. Спорные строки и переводы пропускаются;
изменение времени подтверждается вместе с планом, остальные поля существующих записей сохраняются.
Для PDF Т-Банка бот сверяет количество строк и итоговые суммы, если они указаны в документе.
У переводов отдельно показаны получатель, банк и последние цифры реквизитов, если они есть
в выписке. Недостающие сведения не угадываются; внутренний перевод не означает перевод себе.
Чеки и скриншоты завершённых платежей записываются без подтверждения, включая пачки;
повторы изображения, банковского ID или покупки с тем же продавцом, суммой, счётом и датой
сверяются с книгой, включая написание продавца латиницей и кириллицей. Все строки списка проверяются повторно;
несколько покупок у одного продавца на одном скриншоте сохраняются отдельно.
Без времени на скриншоте используется 12:00 даты операции; переводы пропускаются без вопросов.
Память категорий общая для всех контактов: «Запомни: доход с Авито — продажа вещей». `/memory` — общие правила,
`/forget ID` — удалить; правила сохраняются между перезапусками.
Явное правило для продавца применяется к выпискам, но не снимает проверку дублей;
выбор категории или пояснение к конкретной строке имеет приоритет.

## Запуск

1. Скопируйте `.env.example` в `.env`; укажите токен бота, URL ezBookkeeping и основной счёт.
2. Создайте `.local/data`. Сохраните API token ezBookkeeping в `ezbookkeeping.token`,
   случайный пароль PostgreSQL — в `postgres.password` внутри этой папки. Не публикуйте её.
3. Выполните:

```sh
docker compose pull
docker compose run --rm --user root --cap-add CHOWN --cap-add FOWNER --cap-add DAC_OVERRIDE --entrypoint sh bot -c 'chown -R 1000:1000 /data; chmod 700 /data'
docker compose run --rm bot pair
docker compose run --rm bot login
docker compose run --rm bot warmup
docker compose up -d
```

Откройте одноразовую ссылку из `pair`; контакты добавляются через `/allow ID Имя`.
Все контакты работают с общей книгой. `/help`, `/status`, `/retry` доступны в боте.
Данные PostgreSQL сохраняются в Docker volume; OAuth и настройки — в `.local/data`.

Образы: `ghcr.io/streletskiy/ebk-tg-bot:dev` — каждый коммит dev;
`:0.7.1` и `:latest` — опубликованные стабильные релизы. Поддерживаются amd64 и arm64.

При переходе со старой SQLite остановите бота, сохраните резервную копию и выполните
`docker compose run --rm bot migrate-sqlite --sqlite-path /data/moneybot.sqlite3`
до запуска нового бота. Импорт проверяет все строки и не перезаписывает непустую базу.
Базу ezBookkeeping эта миграция не изменяет.
